# Личный каталог фильмов

Учебный проект: поиск фильмов через [Kinopoisk API Unofficial](https://kinopoiskapiunofficial.tech/) и личные списки просмотра.

## Текущее состояние

Форма поиска подключена к серверной функции: она ищет фильмы через API и возвращает данные карточек. Реализованы сообщения об отсутствии результатов, сбое сети, лимите API и недоступности сервиса. После ошибки поиск можно повторить кнопкой. Автоматические проверки ошибок пройдены без настоящего ключа. Реальный запрос после настройки ключа пользователем и внешний вид агентом ещё не проверены. Опубликованного сайта пока нет.

- Репозиторий GitHub: [kinova](https://github.com/maliksuleimenov11-dotcom/kinova).
- Сайт: ссылка появится после размещения и проверки.

## Планируемые возможности первой версии

- Поиск по названию по кнопке; карточки с постером, названием, годом и рейтингом.
- Списки «Хочу посмотреть» и «Просмотрено» без дублей по ID фильма.
- Личная оценка от 1 до 10 и отзыв до 500 символов.
- Сохранение каталога в localStorage текущего браузера.
- Сообщения об ошибке сети, отсутствии результатов и лимите API.
- Русский интерфейс для компьютера и телефона шириной от 375px.

Это план, а не список уже работающих функций. Каталог не синхронизируется между браузерами; очистка данных браузера удалит записи.

## Личные списки

Из результатов поиска можно добавить фильм в «Хочу посмотреть». В разделе «Мой каталог» видны карточки и счётчик; последнее добавление показывается первым. Фильм с тем же ID повторно не добавляется, даже после нового поиска. Фильмы с одинаковыми названиями и разными ID считаются разными. Добавление не обращается к API.

Теперь из поиска фильм также можно сразу добавить в «Просмотрено». Кнопка «Уже посмотрел» переносит его из планов в просмотренное, «Хочу пересмотреть» возвращает в планы. Счётчики и статусы в поиске обновляются; перенесённая карточка становится первой. Перенос не обращается к API и сохраняет одну запись на ID во всём каталоге.

Списки, личная оценка и отзыв сохраняются в localStorage и восстанавливаются после перезагрузки.

Проверка: найдите фильм и нажмите «Хочу посмотреть»; убедитесь, что он появился в каталоге, а в результате поиска виден статус добавления. Найдите его снова — копии быть не должно. Добавьте другой фильм — счётчик увеличится, новая карточка окажется первой. Выполните поиск без результатов: каталог должен остаться. После перезагрузки он восстанавливается.

Проверка второго шага: добавьте один фильм сразу в «Просмотрено», другой — в «Хочу посмотреть». У второго нажмите «Уже посмотрел»: в планах станет на один фильм меньше, в просмотренном — на один больше. Нажмите «Хочу пересмотреть»: он вернётся в планы. Проверьте, что статус этого фильма в поиске соответствует списку, а Tab после переноса продолжает навигацию от кнопки перенесённой карточки.

Автоматические проверки (`npm test`) дополнены защитой от дублей, разными ID при одинаковом названии, порядком, счётчиками и сохранением списка при пустом результате и ошибке поиска. Проверены также прямое добавление в просмотренное, перенос в обе стороны, повторное нажатие, обновление статуса и вызов перевода фокуса. Проверки пройдены с подменой элементов страницы и ответов API. Внешний вид и реальный клавиатурный фокус ещё требуют ручной проверки. Требования: [списки фильмов](specs/002-spiski-filmov.md).

Итоговые автоматические проверки также подтвердили сохранность обоих заполненных списков при сетевой ошибке и лимите, перенос после ошибки без сети, защиту от повторного ID в одной выдаче, отклонение неверных ID и пустой каталог в новом контексте страницы. Код приложения исправлять не потребовалось. Это проверки логики с подменой элементов страницы; реальный браузер они не заменяют.

Оставшиеся ручные проверки списков:

1. Клавишей Tab перейдите к кнопке добавления, нажмите Enter. Фокус должен оказаться на статусе добавленного фильма; следующий Tab продолжает навигацию.
2. Найдите кнопку переноса в каталоге клавишей Tab, нажмите Enter. Фокус должен перейти к кнопке перенесённой карточки в другом списке.
3. При ширине 375px проверьте пустые и заполненные списки, длинное название и кнопки: горизонтальной прокрутки нет, фокус виден, области кнопок не меньше 44 × 44px.
4. Включите Offline в Network, выполните поиск и после ошибки перенесите ранее добавленный фильм. Каталог должен работать. Отключите Offline.
5. Перезагрузите страницу: оба списка должны восстановиться. Убедитесь, что пояснение о хранении в этом браузере видно рядом с каталогом.

Браузерный инструмент недоступен, поэтому эти ручные проверки агентом не выполнены. Сохранение описано в [отдельной спецификации](specs/003-sohranenie-kataloga.md).

## Сохранение каталога

Добавление и перенос записываются в localStorage текущего сайта. При открытии страницы восстанавливаются оба списка, порядок, данные и счётчики без запроса к API. Если сохранить изменение не удалось, прежний каталог остаётся на месте и появляется сообщение об ошибке; действие можно повторить. При ошибке чтения или повреждении данных запись блокируется, чтобы не затереть сохранённое.

Проверьте: добавьте фильмы в оба списка; перенесите один; запомните порядок и счётчики; нажмите F5. Каталог должен восстановиться. Найдите тот же фильм — статус добавления должен сохраниться, копии быть не должно.

Данные доступны только в этом браузере для этого адреса сайта. Очистка данных сайта удалит каталог; в приватном режиме срок хранения может быть ограничен. Локальный и опубликованный сайт имеют отдельные каталоги. Используйте одну вкладку: одновременные изменения в нескольких вкладках пока не согласуются. Ключ API и выдача поиска в localStorage не записываются.

Автоматические проверки первого шага пройдены на подменённом хранилище: сохранение, восстановление обоих списков и порядка, счётчики, защита от дубля после восстановления, откат при ошибке записи, успешный повтор и сохранность чужого ключа localStorage. Настоящий браузер и API в этих проверках не использовались.

На втором шаге `npm test` дополнен проверками сломанного JSON, неизвестной версии, неверных полей фильма, запрета чтения, ошибки добавления и объединения повторных ID. Проверки прошли: исходные данные не перезаписываются, частичный каталог не восстанавливается, поиск работает при заблокированном добавлении. После восстановления записи действие можно повторить; после ошибки чтения требуется перезагрузка. Неверные данные не исправляются автоматически. Не изменяйте настоящий каталог ради проверки — команда использует только подменённое хранилище. Итоговая проверка сохранения и проверка в браузере ещё впереди.

## Предлагаемый стек

HTML, CSS и JavaScript для страницы; небольшая серверная функция Node.js для API. Размещение — Vercel: сайт и серверная функция в одном проекте. База данных для первой версии не требуется.

Схема: браузер → своя серверная функция → Kinopoisk API Unofficial. Ключ читает только сервер из KINOPOISK_API_KEY. Возможности сервера и окружения описаны в [документации Vercel](https://vercel.com/docs/functions/runtimes) и [настройках переменных](https://vercel.com/docs/environment-variables). Условия хостинга проверить перед публикацией.

## Безопасная настройка ключа

Ключ не нужно отправлять в чат. Самостоятельно создайте .env.local по образцу .env.example и задайте значение локально. На хостинге добавьте KINOPOISK_API_KEY в серверные переменные окружения. .env.local исключён из Git.

Не помещайте ключ в клиентские файлы, публичные переменные, логи, скриншоты и примеры. .env.example всегда остаётся с пустым значением. Открытие HTML двойным щелчком не запускает серверную функцию.

## Как запустить локально

1. Установите актуальную LTS-версию [Node.js](https://nodejs.org/), не ниже 22, и заново откройте терминал. Проверьте командой `node --version`.
2. В папке проекта скопируйте .env.example в .env.local. Откройте .env.local в редакторе и самостоятельно впишите ключ после знака `=`. Не вводите ключ в команду терминала.
3. В терминале из папки проекта выполните `npm start`. Устанавливать зависимости через `npm install` не требуется: внешних зависимостей нет.
4. Откройте http://localhost:3000. Для остановки сервера нажмите Ctrl+C. После изменения ключа перезапустите сервер.

Файл окружения загружается встроенным [параметром Node.js --env-file](https://nodejs.org/api/cli.html#--env-filefile). Локальный сервер доступен только на этом компьютере и отдаёт только HTML, CSS и клиентский JavaScript.

Серверный обработчик находится в api/search.js — формате [Vercel Functions для Node.js](https://vercel.com/docs/functions/runtimes/node-js). Используется [документированный API](https://kinopoiskapiunofficial.tech/documentation/api/): `/api/v2.2/films`, параметры `keyword` и `page=1`, ключ в заголовке `X-API-KEY`. Публикация и её конфигурация — отдельный шаг: до неё нужно настроить ограничение запросов и проверить, какие файлы доступны на хостинге.

## План небольшими шагами

1. Согласовать [правила](AGENTS.md) и [поиск фильмов](specs/001-poisk-filmov.md).
2. После «делай» выполнить первый шаг спецификации: форму и карточки на тестовых данных. Остановиться для проверки.
3. Отдельными шагами подключить серверный поиск, затем обработать ошибки.
4. Перед каждой следующей функцией написать спецификацию: списки и защита от дублей; сохранение; личная оценка и отзыв.
5. Подготовить публичный GitHub-репозиторий и размещение, проверить сайт, добавить реальные ссылки. Коммит и push — после проверки и «да».

## Как проверить сейчас

- Запустите сервер по инструкции выше и откройте http://localhost:3000.
- Введите «Матрица»: до нажатия кнопки поиска запросов нет. Нажмите «Найти»: должны появиться карточки из API. Их число и рейтинги зависят от поставщика данных.
- Введите «Дюна» и нажмите Enter: должен выполниться новый поиск.
- Введите только пробелы и нажмите «Найти»: появится «Введите название фильма».
- При отсутствии совпадений появится сообщение «Ничего не найдено…».
- Откройте инструменты разработчика браузера → «Сеть» (Network), выполните поиск и выберите `/api/search?q=…`. В заголовках и ответе этого запроса ключа быть не должно. Картинки постеров загружаются отдельно.
- Откройте http://localhost:3000/.env.local: должна быть ошибка 404, без содержимого файла.
- С пустым значением в .env.local после перезапуска сервера поиск показывает «Поиск временно недоступен». После проверки самостоятельно верните ключ и перезапустите сервер.
- Проверьте страницу на ширине 375px: нет горизонтальной прокрутки, поле и кнопка удобны. Клавишей Tab перейдите к полю и кнопке: фокус должен быть виден.
- Прочитайте AGENTS.md: правила относятся к фильмам, ключ остаётся на сервере, коммиты требуют вашего «да».
- В specs/001-poisk-filmov.md проверьте поведение поиска, сообщения, ограничения и порядок шагов.
- Убедитесь, что .env.example содержит пустое значение, а .gitignore исключает локальные файлы окружения.

На первом шаге проверена логика формы с подменёнными элементами страницы. На втором проверены синтаксис, параметры и методы серверного запроса, отсутствие ключа, очистка данных карточек, ответы API 401/403/402/429/500. HTTP-проверка локального сервера подтвердила доступность страницы и запрет доступа к .env.local, .git и серверному коду. Настоящий ключ в проверках не использовался. Реальный поиск, визуальная проверка, клавиатура и 375px ещё требуют проверки. Полная проверка ошибок — третий шаг спецификации.

## Личная оценка и отзыв

У фильма в каталоге нажмите «Оценка и отзыв», выберите число от 1 до 10, при желании напишите отзыв и нажмите «Сохранить». Оценка подписана отдельно от рейтинга API. Выбор «Не указана» очищает личную оценку, пустой отзыв удаляет прежний текст. Поля необязательны. «Отмена» оставляет прежние значения. Пока форма открыта, перенос этого фильма недоступен. Открытие формы другого фильма отменяет предыдущий несохранённый ввод — рядом с формой есть пояснение.

Проверьте: поставьте 8, нажмите F5, затем перенесите фильм в другой список. Оценка должна остаться. Откройте форму, выберите другое значение и отмените: прежняя оценка не меняется. При ошибке записи форма остаётся открытой, можно повторить сохранение.

Существующий каталог версии 1 читается без изменения исходной записи. После успешного добавления, переноса или изменения личных полей записывается версия 2. Ошибка записи не заменяет старые данные.

Отзыв ограничен 500 символами после удаления пробелов по краям; переносы строк внутри сохраняются. Счётчик использует кодовые точки Unicode: обычное эмодзи считается одним символом, составное может занимать несколько. Слишком длинный текст не обрезается: форма показывает ошибку и остаётся открытой. Черновик сохраняется при поиске и добавлении другого фильма, но не после перезагрузки без нажатия «Сохранить».

Проверьте отзыв: введите 500 букв и сохраните; добавьте ещё одну — сохранение должно показать ошибку, не теряя ввод. Удалите лишнюю букву и повторите. Отмените другое изменение, затем перенесите фильм и нажмите F5: должен остаться последний сохранённый текст.

Проверки второго шага прошли на подменённых элементах страницы и хранилище: 500/501 символ, эмодзи, счётчик и trim, отмена, ошибка записи с повтором, сохранность черновика при поиске и добавлении, буквальное отображение HTML и переносов строк, восстановление отзыва после переноса, очистка обоих личных полей. Проверка внешнего вида и клавиатуры в браузере остаётся открытой.

Автоматически проверены совместимость формата, сохранение 1, 8 и 10, очистка, отмена, отклонение неверной оценки, ошибка записи с повтором, восстановление и перенос, сохранность рейтинга API и поля отзыва. Прежние проверки поиска, списков и хранения также прошли на подменённых элементах страницы и хранилище. Реальные клавиатура, F5 и ширина 375px ещё требуют ручной проверки. Требования: [оценка и отзыв](specs/004-ocenka-i-otzyv.md).

## Автоматическая проверка ошибок

Итоговые проверки оценки и отзыва пройдены: редактирование сохраняет порядок, статус, счётчики и данные остальных фильмов; черновик выдерживает сетевую ошибку, повторное открытие той же формы и перенос другого фильма. Открытие формы другого фильма отменяет несохранённый ввод предыдущей. Неверные личные поля в хранилище безопасно отклоняются без перезаписи. Эти проверки выполнены на подменённых элементах страницы и хранилище, настоящий API не использовался.

Для ручной проверки личных полей: сохраните оценку и отзыв; перенесите фильм и нажмите F5; измените поля и отмените; затем очистите оба поля и сохраните. Повторите открытие, сохранение и отмену через Tab/Enter. На ширине 375px проверьте длинный отзыв, видимый фокус и отсутствие горизонтальной прокрутки. Браузерный инструмент недоступен, поэтому агент эти проверки не выполнил.

Итоговые проверки сохранения также пройдены: поиск после восстановления показывает оба статуса; пустая выдача, сеть и лимит не меняют списки или строку в localStorage. Перенос восстановленного фильма сохраняется и восстанавливается при следующем открытии. Код приложения исправлять не потребовалось.

Для ручной проверки сохранения запустите сайт, добавьте фильмы в оба списка и перенесите один. Нажмите F5, проверьте порядок и счётчики, затем найдите добавленный фильм снова: должна быть подпись его списка. Повторите перенос через Tab и Enter; на ширине 375px проверьте кнопки, видимый фокус и отсутствие горизонтальной прокрутки. Настоящий каталог не повреждайте ради тестирования ошибок. Эти браузерные проверки агентом не выполнены: браузерный инструмент недоступен.

Из папки проекта выполните `npm test` (нужен Node.js 22 или новее). Ключ, .env.local и установка зависимостей для этой команды не нужны. Проверки из tests/search.cjs используют подменённые ответы, не отправляют запросы в Kinopoisk и не расходуют квоту.

Проверяются форма и карточки, отсутствие запросов при наборе и пустом вводе, блокировка повторной отправки, пустая выдача, отсутствующие поля, сломанный постер, сеть, тайм-аут, лимит, неверный ответ сервера и успешный поиск после ошибки. Серверный таймер моделируется без ожидания восьми секунд. Эти проверки пройдены через Node.js-инструмент; интерфейс проверяется с подменой элементов страницы, поэтому реальное поведение браузера и внешний вид они не подтверждают.

Для ручной проверки сети запустите приложение, откройте инструменты разработчика → Network и включите Offline. Нажмите «Найти»: появится ошибка, кнопка снова станет доступной. Отключите Offline и повторите поиск. При настроенном ключе должны появиться результаты. Лимит API проверяйте только командой `npm test`, не расходуйте реальную квоту специально.

Ещё требуется проверить настоящий поиск, отсутствие ключа в запросах браузера, клавиатуру и ширину 375px по инструкции выше. Защиту от частых запросов на публичном хостинге подготовим перед размещением.
