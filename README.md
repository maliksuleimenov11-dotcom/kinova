# Личный каталог фильмов

Учебный проект для поиска фильмов и ведения личного каталога.

- Сайт: [kinova-sigma.vercel.app](https://kinova-sigma.vercel.app/).
- Публичный код: [GitHub — kinova](https://github.com/maliksuleimenov11-dotcom/kinova).
- Данные фильмов: [Kinopoisk API Unofficial](https://kinopoiskapiunofficial.tech/).

## Состояние проекта

Возможности первой версии реализованы и размещены на Vercel. Пользователь подтвердил работу настоящего поиска, а затем сообщил «всё работает» после предложенной проверки добавления, переноса, оценки, отзыва, обновления страницы и сайта на телефоне. Это подтверждение пользователя; агент не выполнял эти действия в браузере.

Автоматические проверки пройдены на подменённых элементах страницы, API и localStorage. Отдельная проверка точной ширины 375px, размеров элементов 44px, клавиатуры, фокуса и отсутствия ключа в Network браузера пока не подтверждена.

## Возможности

- Поиск по названию кнопкой «Найти» или Enter, без запросов при наборе.
- Первая страница карточек с постером, названием, годом и рейтингом API; заглушки отсутствующих данных.
- Списки «Хочу посмотреть» и «Просмотрено», счётчики и перенос в обе стороны.
- Одна запись на ID фильма; одинаковые названия с разными ID считаются разными фильмами.
- Личная оценка от 1 до 10 и необязательный отзыв до 500 символов, сохранение и отмена.
- Сохранение каталога в localStorage и восстановление списков, порядка, оценки и отзыва после перезагрузки.
- Сообщения об отсутствии результатов, ошибке сети, недоступности сервиса, квоте API и частых запросах к сайту.
- Русский интерфейс; предусмотрены мобильная вёрстка, подписи полей и видимый фокус.

## Поиск в моём каталоге — новое

В разделе «Мой каталог» введите часть названия и нажмите «Найти в каталоге» или Enter. Поиск работает сразу в обоих сохранённых списках без учёта регистра и пробелов по краям. Во время набора результат не меняется. Счётчики показывают число совпадений и полное количество фильмов. «Показать все» очищает запрос и возвращает все карточки; пустой запрос делает то же самое.

Это отдельный локальный поиск: он не обращается к API и не расходует его лимит. Карточки только скрываются — каталог и черновик отзыва не удаляются. После перезагрузки запрос сбрасывается, сохранённые фильмы остаются. Фильтры по оценке и сортировка не добавлены.

Проверка: найдите часть названия сохранённого фильма, перенесите совпавший фильм в другой список, затем нажмите «Показать все». Убедитесь, что весь каталог вернулся. При неизвестном названии должно появиться сообщение об отсутствии совпадений. На телефоне проверьте форму и кнопки, клавишами Tab/Enter — управление.

Автоматические проверки и сборка прошли через Node.js-инструмент: часть названия, регистр, пробелы, поиск по запасному названию, оба списка, счётчики, отсутствие совпадений, пустой запрос, сброс, слишком длинный ввод, сохранность черновика, перенос и отсутствие сетевых запросов. Пока не выполнены проверка нового интерфейса в настоящем браузере и публикация изменения.

## Как пользоваться и проверить

1. Откройте сайт, введите «Матрица» и нажмите «Найти». Во время ввода запросов нет; состав выдачи зависит от API.
2. Добавьте фильм в «Хочу посмотреть». Найдите его снова: вместо кнопок добавления должен быть статус, без копии в каталоге.
3. Нажмите «Уже посмотрел», затем «Хочу пересмотреть»: фильм переносится, счётчики обновляются.
4. Откройте «Оценка и отзыв», выберите оценку и напишите текст. Сохраните; рейтинг API не должен измениться.
5. Измените личные поля и отмените: останутся прежние значения. «Не указана» и пустой отзыв позволяют очистить поля.
6. Проверьте 500 и 501 символ: лишний текст не обрезается, сохранение показывает ошибку. Счётчик считает кодовые точки Unicode после удаления пробелов по краям; обычное эмодзи занимает одну, составное — несколько.
7. Перенесите фильм и обновите страницу: каталог и личные поля должны остаться.
8. Проверьте Tab/Enter и ширину 375px: поля и кнопки доступны, фокус виден, горизонтальной прокрутки нет, поля высотой от 44px и области кнопок от 44 × 44px.

Одновременно открыта одна форма. Открытие формы другого фильма отменяет предыдущий несохранённый ввод. Поиск и обновление каталога сохраняют открытый черновик; F5 без «Сохранить» его сбрасывает. Перенос редактируемого фильма заблокирован.

## Ограничения хранения

Каталог доступен только в этом браузере для текущего адреса сайта. Очистка данных сайта удалит фильмы; приватный режим может ограничить срок хранения. Каталог не синхронизируется между устройствами, браузерами и вкладками. Используйте одну вкладку: более поздняя запись другой вкладки может заменить изменения. У локального сайта и сайта Vercel отдельные каталоги.

При ошибке записи изменение не применяется: прежние данные остаются, форму можно сохранить повторно. При ошибке чтения или повреждении данных изменение каталога блокируется без перезаписи; поиск работает. Автоматического восстановления повреждённых данных нет. Не очищайте настоящий каталог ради теста.

Хранилище kinova.catalog читает версии 1 и 2 и записывает версию 2. Старые данные не перезаписываются при загрузке; перевод формата происходит при успешном изменении. Ключ API и результаты поиска в каталог не записываются.

## Стек и безопасность

HTML, CSS и JavaScript для страницы, серверная функция Node.js на Vercel. База данных и регистрация не используются.

Браузер → /api/search → Kinopoisk API Unofficial. Только сервер читает KINOPOISK_API_KEY и передаёт его API в заголовке. В Git, клиентские файлы, примеры и логи ключ не добавляется. Пользователь самостоятельно настроил Secret-переменную для Production на Vercel; агент значение не получал.

На Vercel настроено правило Request Path → Starts With → /api/search: Fixed Window, 10 запросов за 60 секунд на IP, действие 429. До подключения ключа проверен общий порог для /api/search и /api/search.js: первые десять чередующихся запросов получили 503, затем оба маршрута — 429. Это не защита общей квоты от множества IP; счётчики хостинга могут зависеть от региона. Другие домены проекта отдельно не проверены.

Страница по HTTP проверена (200); /.env.local, /.git/config, /server.cjs, /tests/search.cjs и /README.md дали 404. /api/search.js — дополнительный маршрут функции, исходник не раскрывает. Клиент различает 429 хостинга с произвольным телом и ответ API_LIMIT от сервера. Обновлённая обработка подтверждена в опубликованном script.js.

В Network браузера дополнительно проверьте запрос /api/search: ключа в его заголовках и ответе быть не должно. Постеры загружаются отдельно с внешних адресов.

## Локальный запуск

1. Установите [Node.js 22.x](https://nodejs.org/) и откройте новый терминал.
2. В папке проекта скопируйте .env.example в .env.local. Самостоятельно задайте значение KINOPOISK_API_KEY в редакторе; ключ не отправляйте в чат и не вводите в команду терминала.
3. Выполните npm start и откройте http://localhost:3000. Зависимостей нет, npm install не требуется.
4. Для остановки нажмите Ctrl+C. После изменения окружения перезапустите сервер.

.env.local исключён из Git. .env.example остаётся с пустым значением. Открытие HTML двойным щелчком не запускает серверную функцию.

## Проверки и сборка

- npm test — воспроизводимые проверки без ключа, настоящего API и изменения вашего каталога.
- npm run build — сборка без ключа в dist: только index.html, styles.css и script.js.

Проверены поиск и ошибки, дубли, оба списка, перенос, сохранение и восстановление, сбои хранилища, повреждённые данные, совместимость формата, оценка, 500/501 символ, эмодзи, черновик, отмена и HTML как текст. Таймеры моделируются. Это проверки логики с подменой элементов страницы, а не полноценный браузерный тест.

Сборка и повторная сборка проверены: три файла совпадают с исходниками. Посторонние файлы в dist останавливают сборку без автоматического удаления. Файл окружения не копируется. dist исключён из Git.

## Размещение на Vercel

Репозиторий подключён к Vercel; push автоматически запускает размещение. В vercel.json: Other, команда npm run build, Output Directory dist, функция api/search.js с максимумом 15 секунд. В package.json закреплён Node.js 22.x. .vercelignore исключает локальное окружение и служебные файлы при загрузке CLI; публичные файлы ограничены папкой dist.

Для повторного размещения сначала настройте правило Firewall без настоящего ключа. Затем самостоятельно добавьте KINOPOISK_API_KEY как Secret для Production и выполните Redeploy. Preview ключ не получает. Изменения окружения применяются к новому размещению. [Документация окружения Vercel](https://vercel.com/docs/environment-variables/managing-environment-variables).

Следите за расходом запросов в личном кабинете Kinopoisk API Unofficial. Для отключения настоящего поиска удалите серверную переменную ключа и выполните Redeploy. Прежние размещения сохраняют прежнее окружение: при необходимости отдельно ограничьте доступ к ним в Vercel. Платные услуги автоматически не подключались.

## Экспорт и импорт каталога

В «Моём каталоге» кнопка «Скачать каталог» подготавливает JSON-файл kinova-catalog-YYYY-MM-DD.json с локальной датой браузера. Выгружается весь сохранённый каталог: оба списка, порядок, оценки и отзывы, включая скрытые локальным поиском фильмы. Несохранённый черновик в файл не попадает и остаётся на странице. Пользователь сам выбирает сохранение или отмену скачивания.

«Выбрать файл каталога» проверяет JSON до 5 МиБ и показывает имя, число уникальных, новых, существующих фильмов и повторных ID. Поддерживаются версии 1 и 2. До подтверждения ничего не записывается. «Отмена импорта» оставляет каталог прежним. При открытом редакторе сначала сохраните или отмените его.

«Добавить из файла» добавляет только новые ID. Существующие фильмы целиком сохраняют свои списки, оценки и отзывы. При повторном импорте — «Новых фильмов нет», без записи. В пустом каталоге восстанавливается порядок файла; при объединении новые фильмы показываются перед текущими в каждом списке. После успеха локальный поиск сбрасывается, статусы внешней выдачи обновляются.

При ошибке записи каталог не меняется, можно повторить или отменить. Если другая вкладка изменила хранилище, импорт останавливается без перезаписи и требует перезагрузки. Повреждённые данные и файл больше 5 МиБ отклоняются. При ошибке чтения текущего каталога экспорт и импорт заблокированы. Работайте в одной вкладке.

Всё выполняется локально, без отправки файла серверу и расхода API. Постеры представлены адресами, а не изображениями. Файл содержит личные отзывы — храните его у себя и не добавляйте настоящие резервные копии в Git.

Итоговые автоматические проверки и сборка прошли через Node.js-инструмент. Проверен полный цикл: сформированный экспорт → независимый пустой каталог → повторное открытие → повторный импорт без дублей. Полное содержимое сохранённых данных совпало с экспортом; оценки, отзывы и оба статуса восстановлены. Проверены отмена, форматы 1/2, размер до чтения, повреждённые файлы, ошибка записи с повтором, другая вкладка, отсутствие сетевых запросов при переносе и обновление статусов выдачи. Код приложения исправлять не потребовалось. HTTP-проверка опубликованного script.js подтвердила наличие подтверждения импорта.

Ручная проверка пользователем:

1. Скачайте каталог при активном локальном поиске и убедитесь, что файл содержит также скрытые фильмы; открытый черновик отзыва не должен потеряться.
2. Откройте сайт в другом браузере с пустым каталогом, выберите файл, сверьте числа и подтвердите импорт. Проверьте списки, порядок, оценки и отзывы, затем нажмите F5.
3. Импортируйте тот же файл повторно: новых фильмов быть не должно. Отмена предварительного результата также не должна менять данные.
4. Пройдите скачивание, выбор, отмену и подтверждение клавиатурой; проверьте видимый фокус и ширину 375px без горизонтальной прокрутки.

Настоящие скачивание и диалог выбора, перенос между браузерами, клавиатура и точные размеры агентом не проверены: браузерный инструмент недоступен. Автоматические проверки используют подменённые элементы страницы и хранилище, поэтому не заменяют эти действия. Итоговые изменения тестов и документации пока ожидают согласованного коммита.

## Удаление с отменой

В обоих списках у карточки есть «Удалить из каталога». После успешной записи фильм исчезает, появляется «Отменить удаление». Отмена возвращает его в прежний список и на прежнее место вместе с оценкой и отзывом. Если фильм есть в результатах поиска, статус добавления тоже обновляется. Запросов к API нет.

Отмена доступна только для последнего удаления, до следующего успешного сохранённого изменения каталога или F5. Таймера нет. После перезагрузки удалённый фильм не возвращается; отдельной корзины нет. Ранее скачанный файл каталога не меняется. Повторное добавление фильма из поиска не восстанавливает старые личные поля — для этого нужна отмена.

При ошибке записи фильм остаётся на месте, при ошибке отмены можно повторить восстановление. Если данные изменила другая вкладка, действие блокируется до перезагрузки без перезаписи чужих изменений. Удаление редактируемого фильма и действия с каталогом во время предварительного импорта недоступны.

Проверьте локально: удалите средний фильм, отмените и сверьте его место, оценку и отзыв. Повторите в «Просмотрено». Затем удалите фильм и нажмите F5 — он должен остаться удалённым без кнопки отмены. Для проверки используйте тестовую запись или заранее скачайте резервную копию.

Автоматически проверены оба списка, порядок при отмене, личные поля, одинаковые названия с разными ID, повторные действия, ошибки записи с повтором, отсутствие отмены после повторной инициализации страницы и конфликт другой вкладки. Реальные пользовательские фильмы не удалялись. Первый шаг отправлен в GitHub; подробная ручная проверка остаётся открытой.

На втором шаге проверки подтвердили: поиск и экспорт сохраняют отмену; открытие и отмена редактора также её сохраняют. Ошибка сохранения другого фильма не завершает отмену, успешное сохранение — завершает. То же правило действует при добавлении, переносе и импорте. Во время предварительного импорта удаление и отмена заблокированы; после его отмены возможность восстановления возвращается. Повторное добавление удалённого фильма не возвращает его старые личные поля. Удаление и отмена обновляют статус внешней выдачи без нового запроса API.

Проверка второго шага: удалите тестовый фильм и выполните поиск — отмена должна остаться. Откройте редактор другого фильма, начните отзыв, отмените удаление — черновик должен остаться. После успешного изменения каталога прежняя отмена исчезает. На двух удалениях подряд отменяется только последнее.

Итоговые автоматические проверки и сборка прошли через Node.js-инструмент. Проверен полный цикл для последнего фильма в каждом списке: удаление → пустой каталог и экспорт → отмена → повторное открытие. Все поля восстановленного фильма совпали с исходными. Проверено, что неудачное второе удаление сохраняет возможность отменить первое. Код приложения исправлять не потребовалось; реальные пользовательские фильмы не удалялись.

Оставшаяся ручная проверка: на тестовой карточке выполните удаление и отмену в обоих списках, сверьте место, оценку и отзыв и обновите страницу. Повторите удаление без отмены и F5 — фильм должен остаться удалённым. Пройдите кнопки через Tab/Enter, проверьте фокус на отмене и восстановленной карточке, а также вид на 375px. При необходимости заранее скачайте резервную копию. Реальный браузер, клавиатура и размеры агентом не проверены; автоматические проверки используют подменённые элементы страницы и хранилище. Итоговые изменения тестов и документации пока ожидают согласованного коммита.

## Подборки фильмов — второй шаг

В «Что посмотреть» выберите «Популярные сейчас» или «Премьеры месяца» и нажмите «Показать подборку». Для премьер доступны текущий и предыдущий месяцы по UTC+5. Изменение полей не загружает данные; заголовок уже показанной выдачи остаётся прежним до отправки.

Тестовые фильмы удалены: клиент обращается к своей серверной функции /api/search-discover, а она — к Kinopoisk API Unofficial с серверным ключом. Популярные — текущая коллекция TOP_POPULAR_MOVIES, премьеры — российские даты выхода выбранного месяца. В самой выдаче премьер нет рейтинга: показано «Нет рейтинга», без запросов за деталями каждого фильма. Показываются первые 20 уникальных карточек. Добавление из подборок в каталог появится следующим шагом.

Успешные ответы имеют часовой TTL для CDN Vercel; ошибки — no-store. В открытой странице уже загруженная подборка в течение часа показывается из памяти без нового fetch, после часа запрос выполняется только по следующему нажатию. Подборки расходуют общий лимит API; кеш снижает расход, но не гарантирует один запрос в час для всех регионов и размещений. После отключения серверного ключа уже кешированные общедоступные карточки могут оставаться до часа; для немедленного отключения нужен сброс кеша Vercel. Личные статусы, оценки и отзывы в CDN не передаются.

Проверены новые пути /api/search-discover и /api/search-discover.js на текущем правиле Firewall Starts With /api/search: десять чередующихся тестовых запросов получили 404 (маршрут ещё не был опубликован), затем оба пути вернули 429. Параметр kind=invalid исключал обращение к внешнему API. После размещения требуется повторить обычную проверку маршрута и отдельно подтвердить фактический CDN HIT; одни заголовки кеша его не доказывают.

Проверка второго шага: запустите npm start с самостоятельно настроенным .env.local, загрузите оба вида подборок. Повторное нажатие для уже загруженной подборки в течение часа не должно создавать запрос в Network. На опубликованном сайте откройте Network для /api/search-discover и проверьте X-Vercel-Cache при повторных запросах из нового контекста страницы. Не добавляйте случайные параметры для обхода кеша и не выполняйте нагрузочный тест настоящего API.

Автоматические проверки прошли без настоящего ключа: разрешённые параметры и месяцы, декабрь/январь, оба адреса API поставщика, нормализация карточек и даты, дубли и лимит 20, один внешний запрос, 401/403/402/429/500, тайм-аут, no-store ошибок, TTL успеха, повторный показ до и после часа, 429 хостинга с HTML и сохранность личного каталога. npm test запускает также tests/discover.cjs. Проверены локальные маршруты с неверными параметрами; прежние тесты и сборка прошли.

Реальный API подборок, CDN HIT, клавиатура и 375px на этом шаге ещё не проверены. Новая серверная загрузка пока локальная, до согласованного коммита и push.
