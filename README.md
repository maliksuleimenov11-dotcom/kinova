# Личный каталог фильмов

Учебный проект: поиск фильмов через [Kinopoisk API Unofficial](https://kinopoiskapiunofficial.tech/) и личные списки просмотра.

## Текущее состояние

Форма поиска подключена к серверной функции: она ищет фильмы через API и возвращает данные карточек. Реализованы сообщения об отсутствии результатов, сбое сети, лимите API и недоступности сервиса. После ошибки поиск можно повторить кнопкой. Автоматические проверки ошибок пройдены без настоящего ключа. Реальный запрос после настройки ключа пользователем и внешний вид агентом ещё не проверены. Опубликованного сайта пока нет.

- Репозиторий GitHub: [kinova](https://github.com/maliksuleimenov11-dotcom/kinova).
- Сайт: ссылка появится после размещения и проверки.

## Планируемые возможности первой версии

- Поиск по названию по кнопке; карточки с постером, названием, годом и рейтингом.
- Списки «Хочу посмотреть» и «Просмотрено» без дублей по ID фильма.
- Личная оценка от 1 до 10 и отзыв до 500 символов.
- Сохранение каталога в localStorage текущего браузера.
- Сообщения об ошибке сети, отсутствии результатов и лимите API.
- Русский интерфейс для компьютера и телефона шириной от 375px.

Это план, а не список уже работающих функций. Каталог не синхронизируется между браузерами; очистка данных браузера удалит записи.

## Предлагаемый стек

HTML, CSS и JavaScript для страницы; небольшая серверная функция Node.js для API. Размещение — Vercel: сайт и серверная функция в одном проекте. База данных для первой версии не требуется.

Схема: браузер → своя серверная функция → Kinopoisk API Unofficial. Ключ читает только сервер из KINOPOISK_API_KEY. Возможности сервера и окружения описаны в [документации Vercel](https://vercel.com/docs/functions/runtimes) и [настройках переменных](https://vercel.com/docs/environment-variables). Условия хостинга проверить перед публикацией.

## Безопасная настройка ключа

Ключ не нужно отправлять в чат. Самостоятельно создайте .env.local по образцу .env.example и задайте значение локально. На хостинге добавьте KINOPOISK_API_KEY в серверные переменные окружения. .env.local исключён из Git.

Не помещайте ключ в клиентские файлы, публичные переменные, логи, скриншоты и примеры. .env.example всегда остаётся с пустым значением. Открытие HTML двойным щелчком не запускает серверную функцию.

## Как запустить локально

1. Установите актуальную LTS-версию [Node.js](https://nodejs.org/), не ниже 22, и заново откройте терминал. Проверьте командой `node --version`.
2. В папке проекта скопируйте .env.example в .env.local. Откройте .env.local в редакторе и самостоятельно впишите ключ после знака `=`. Не вводите ключ в команду терминала.
3. В терминале из папки проекта выполните `npm start`. Устанавливать зависимости через `npm install` не требуется: внешних зависимостей нет.
4. Откройте http://localhost:3000. Для остановки сервера нажмите Ctrl+C. После изменения ключа перезапустите сервер.

Файл окружения загружается встроенным [параметром Node.js --env-file](https://nodejs.org/api/cli.html#--env-filefile). Локальный сервер доступен только на этом компьютере и отдаёт только HTML, CSS и клиентский JavaScript.

Серверный обработчик находится в api/search.js — формате [Vercel Functions для Node.js](https://vercel.com/docs/functions/runtimes/node-js). Используется [документированный API](https://kinopoiskapiunofficial.tech/documentation/api/): `/api/v2.2/films`, параметры `keyword` и `page=1`, ключ в заголовке `X-API-KEY`. Публикация и её конфигурация — отдельный шаг: до неё нужно настроить ограничение запросов и проверить, какие файлы доступны на хостинге.

## План небольшими шагами

1. Согласовать [правила](AGENTS.md) и [поиск фильмов](specs/001-poisk-filmov.md).
2. После «делай» выполнить первый шаг спецификации: форму и карточки на тестовых данных. Остановиться для проверки.
3. Отдельными шагами подключить серверный поиск, затем обработать ошибки.
4. Перед каждой следующей функцией написать спецификацию: списки и защита от дублей; сохранение; личная оценка и отзыв.
5. Подготовить публичный GitHub-репозиторий и размещение, проверить сайт, добавить реальные ссылки. Коммит и push — после проверки и «да».

## Как проверить сейчас

- Запустите сервер по инструкции выше и откройте http://localhost:3000.
- Введите «Матрица»: до нажатия кнопки поиска запросов нет. Нажмите «Найти»: должны появиться карточки из API. Их число и рейтинги зависят от поставщика данных.
- Введите «Дюна» и нажмите Enter: должен выполниться новый поиск.
- Введите только пробелы и нажмите «Найти»: появится «Введите название фильма».
- При отсутствии совпадений появится сообщение «Ничего не найдено…».
- Откройте инструменты разработчика браузера → «Сеть» (Network), выполните поиск и выберите `/api/search?q=…`. В заголовках и ответе этого запроса ключа быть не должно. Картинки постеров загружаются отдельно.
- Откройте http://localhost:3000/.env.local: должна быть ошибка 404, без содержимого файла.
- С пустым значением в .env.local после перезапуска сервера поиск показывает «Поиск временно недоступен». После проверки самостоятельно верните ключ и перезапустите сервер.
- Проверьте страницу на ширине 375px: нет горизонтальной прокрутки, поле и кнопка удобны. Клавишей Tab перейдите к полю и кнопке: фокус должен быть виден.
- Прочитайте AGENTS.md: правила относятся к фильмам, ключ остаётся на сервере, коммиты требуют вашего «да».
- В specs/001-poisk-filmov.md проверьте поведение поиска, сообщения, ограничения и порядок шагов.
- Убедитесь, что .env.example содержит пустое значение, а .gitignore исключает локальные файлы окружения.

На первом шаге проверена логика формы с подменёнными элементами страницы. На втором проверены синтаксис, параметры и методы серверного запроса, отсутствие ключа, очистка данных карточек, ответы API 401/403/402/429/500. HTTP-проверка локального сервера подтвердила доступность страницы и запрет доступа к .env.local, .git и серверному коду. Настоящий ключ в проверках не использовался. Реальный поиск, визуальная проверка, клавиатура и 375px ещё требуют проверки. Полная проверка ошибок — третий шаг спецификации.

## Автоматическая проверка ошибок

Из папки проекта выполните `npm test` (нужен Node.js 22 или новее). Ключ, .env.local и установка зависимостей для этой команды не нужны. Проверки из tests/search.cjs используют подменённые ответы, не отправляют запросы в Kinopoisk и не расходуют квоту.

Проверяются форма и карточки, отсутствие запросов при наборе и пустом вводе, блокировка повторной отправки, пустая выдача, отсутствующие поля, сломанный постер, сеть, тайм-аут, лимит, неверный ответ сервера и успешный поиск после ошибки. Серверный таймер моделируется без ожидания восьми секунд. Эти проверки пройдены через Node.js-инструмент; интерфейс проверяется с подменой элементов страницы, поэтому реальное поведение браузера и внешний вид они не подтверждают.

Для ручной проверки сети запустите приложение, откройте инструменты разработчика → Network и включите Offline. Нажмите «Найти»: появится ошибка, кнопка снова станет доступной. Отключите Offline и повторите поиск. При настроенном ключе должны появиться результаты. Лимит API проверяйте только командой `npm test`, не расходуйте реальную квоту специально.

Ещё требуется проверить настоящий поиск, отсутствие ключа в запросах браузера, клавиатуру и ширину 375px по инструкции выше. Защиту от частых запросов на публичном хостинге подготовим перед размещением.
