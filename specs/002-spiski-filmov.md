# 002 — Списки фильмов

Статус: реализация размещена на https://kinova-sigma.vercel.app/ . Пользователь подтвердил работу настоящего поиска, добавления, переноса, оценки, отзыва, восстановления после обновления страницы и сайта на телефоне. Автоматические проверки пройдены ранее. Точные 375px/44px, клавиатура, фокус и Network браузера отдельно не подтверждены; эти пункты остаются открытыми. Текущее обновление документации не является разрешением на коммит и push.

## Для кого и зачем

Для человека, который находит интересные фильмы и хочет разделять планы на просмотр и уже просмотренное. Каталог доступен на той же странице, что и поиск.

## Что должно быть

- Под результатами поиска — раздел «Мой каталог» с двумя списками: «Хочу посмотреть» и «Просмотрено». У каждого заголовка — количество фильмов.
- Пустые списки показывают «Пока нет фильмов. Добавьте фильм из поиска».
- На карточке результата поиска доступны кнопки «Хочу посмотреть» и «Просмотрено». Нажатие добавляет фильм в выбранный список.
- Сохранённая карточка содержит ID, название, год, рейтинг API и постер. Применяются те же заглушки отсутствующих данных, что и в поиске.
- Один ID фильма соответствует одной записи во всём каталоге. Повторное нажатие и новый поиск не создают копий. Название не используется как признак совпадения.
- Для фильма, который уже добавлен, в результатах виден его текущий статус: «В списке „Хочу посмотреть“» или «В списке „Просмотрено“». Кнопки добавления заменяются статусом; перенос доступен в каталоге.
- В «Хочу посмотреть» у карточки есть кнопка «Уже посмотрел»; в «Просмотрено» — «Хочу пересмотреть». Нажатие переносит существующую запись в другой список. Общее количество записей не меняется.
- Новое добавление или перенос ставит фильм в начало соответствующего списка. Остальные записи сохраняют порядок.
- Новый поиск, пустой результат и ошибка API не очищают каталог. Добавление и перенос не вызывают API и не расходуют квоту.
- Сообщения «Фильм добавлен в „Хочу посмотреть“», «Фильм добавлен в „Просмотрено“» и «Фильм перенесён…» доступны для программ чтения с экрана.
- После переноса клавиатурный фокус переходит на кнопку перенесённой карточки в новом списке. Если карточка результата поиска обновилась после добавления, фокус переходит на её статус с возможностью продолжить навигацию Tab.
- Русский интерфейс, ширина 375px без горизонтальной прокрутки. Области нажатия кнопок минимум 44 × 44px; видимый фокус.

## Примеры

1. Найти «Матрица», нажать «Хочу посмотреть»: одна карточка появляется в этом списке; у результата виден статус добавления. Повторное действие с тем же ID не увеличивает количество.
2. Выполнить другой поиск, затем снова найти тот же фильм: статус добавления сохраняется, второй карточки в каталоге нет.
3. Добавить два фильма с одинаковым названием, но разными ID: появляются две отдельные записи. Две выдачи с одним ID и различающимися названиями соответствуют одной записи.
4. Нажать «Уже посмотрел»: фильм исчезает из «Хочу посмотреть», появляется в «Просмотрено», оба счётчика обновляются. Нажать «Хочу пересмотреть»: фильм возвращается без дубля.
5. Добавить один фильм сразу в «Просмотрено»: в «Хочу посмотреть» он не появляется.
6. После добавления вызвать ошибку поиска или получить пустую выдачу: каталог не меняется, перенос по-прежнему работает.
7. Добавить фильм без постера, года или рейтинга: вместо пропущенных значений видны понятные заглушки.
8. После перезагрузки страницы каталог пока пуст. На этом этапе рядом с каталогом явно написано «Пока хранится только до перезагрузки страницы». Постоянное сохранение появится отдельной функцией.

## Ограничения

- В этой спецификации каталог хранится только в памяти открытой страницы. localStorage, восстановление после перезагрузки, личная оценка и отзыв — следующие отдельные спецификации. До сохранения это ограничение обязательно показывать пользователю.
- Без удаления фильмов, фильтрации, сортировки пользователем, регистрации и синхронизации устройств в этой функции.
- Данные каталога не отправляются серверу. Ключ по-прежнему доступен только серверной функции поиска.
- Не добавлять фильм без корректного положительного целого ID. Защита от дублей работает в логике каталога, даже если кнопку нажали повторно или один фильм несколько раз встретился в результатах.
- Проверки используют подменённые фильмы с известными ID, поэтому не требуют настоящего API и не расходуют квоту.
- Непроверенные пункты спецификации 001 — настоящий API, клавиатура и 375px — остаются открытыми; эта функция не означает их завершения.

Примечание к прежним записям: описания проверок ниже фиксируют состояние на соответствующем этапе. Текущий итог указан в начале файла; сообщение пользователя подтверждает основные сценарии, но не заменяет детальные измерения и проверки доступности.

1. [ ] Добавление в «Хочу посмотреть» и защита от дублей. Появляются «Мой каталог», список со счётчиком и предупреждение о временном хранении. Проверка: добавить фильм; снова найти его и убедиться, что копии нет; добавить другой ID с таким же названием и увидеть отдельную карточку.
2. [ ] Список «Просмотрено», прямое добавление и перенос в обе стороны. Проверка: добавить фильм сразу в «Просмотрено»; перенести другой фильм туда и обратно; проверить счётчики, порядок и статусы в поиске.
3. [ ] Проверка всей функции и документация. Проверка: вызвать ошибку поиска и убедиться, что каталог остался; пройти добавление и перенос клавиатурой; проверить 375px и предупреждение о сбросе после перезагрузки. Дополнить автоматические проверки для дублей и переноса, обновить README.

Проверено отсутствие сетевого запроса при добавлении. Все проверки пройдены через Node.js-инструмент с подменёнными элементами страницы и ответами API. Настоящий ключ не использовался. Внешний вид на 375px и фактический клавиатурный фокус в браузере пока не проверены; первый шаг оставлен без флажка до ручной проверки. Проверки второго шага: tests/search.cjs дополнен прямым добавлением в «Просмотрено», переносом в обе стороны, повторным вызовом действия переноса, счётчиками, общим количеством, порядком карточек, пустым списком и обновлением статуса поиска. Все проверки пройдены через Node.js-инструмент на подменённых элементах страницы и ответах API. Настоящий API, внешний вид на 375px и фактическая навигация клавиатурой остаются непроверенными; шаги не отмечены полностью завершёнными до ручной проверки.

Проверки пройдены через Node.js-инструмент без ключа и запросов к настоящему API. Ошибок приложения в этих сценариях не обнаружено, код приложения не изменялся.
