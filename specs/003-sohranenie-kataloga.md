# 003 — Сохранение личного каталога

Статус: первый шаг принят пользователем для коммита. На втором шаге расширены и пройдены проверки формата, повреждения данных и недоступности хранилища. Код приложения исправлять не потребовалось. Итоговая и ручная проверки — следующий шаг.

Проверки второго шага: tests/search.cjs дополнен сломанным JSON, null, массивом вместо объекта, неизвестной версией, неверным films и ошибочными полями фильма (ID, статус, название, год, рейтинг, адрес постера). Проверены отсутствие частичного восстановления, сохранность исходной строки и чужого ключа, работа поиска при блокировке добавления, отказ чтения и восстановление после повторного открытия с доступным чтением. Проверены повторные ID с приоритетом первой записи без автоматической перезаписи, ошибка добавления при недоступной записи и успешный повтор. Все проверки пройдены через Node.js-инструмент на подменённом хранилище без настоящего ключа и API. Реальный браузер, клавиатура и 375px остаются непроверенными.

## Для кого и зачем

Для человека, который хочет вернуться на сайт и увидеть ранее добавленные фильмы в своих списках. Перезагрузка и закрытие страницы больше не должны сбрасывать каталог.

## Что должно быть

- После успешного добавления или переноса каталог записывается в localStorage текущего сайта. Записываются только ID, название, год, рейтинг API, адрес постера и статус списка.
- После открытия сайта данные восстанавливаются без запроса к API: оба списка, порядок карточек и счётчики. В результатах нового поиска уже добавленный фильм получает правильный статус.
- Новая запись и перенос по-прежнему ставят фильм первым в соответствующем списке. Порядок сохраняется после перезагрузки.
- Один ID соответствует одной записи во всём каталоге, включая восстановленные данные.
- На странице вместо предупреждения о сбросе появляется текст «Каталог сохраняется в этом браузере. Очистка данных сайта удалит фильмы». Ограничения также описаны в README.
- У пустого хранилища нет ошибки: показываются два пустых списка.
- Чтение localStorage, разбор JSON и запись обрабатываются безопасно. Ошибки не ломают поиск и не выводят технический текст посетителю.
- Если запись запрещена или место закончилось, действие добавления или переноса не применяется: прежний каталог и порядок остаются. Сообщение: «Не удалось сохранить изменения. Проверьте доступ к хранилищу браузера и попробуйте снова». Не показывать сообщение об успешном действии.
- После ошибки записи можно повторить действие. Если запись снова доступна, изменение сохраняется и сообщение об ошибке исчезает.
- Если чтение запрещено, показать «Не удалось прочитать каталог. Проверьте доступ к хранилищу и перезагрузите страницу». Поиск продолжает работать, изменение каталога заблокировано до успешной перезагрузки, чтобы не затереть старые данные.
- Если JSON повреждён, формат неизвестен или запись каталога не проходит проверку, показать «Не удалось восстановить каталог. Сохранённые данные оставлены без изменений». Не перезаписывать и не удалять их автоматически. Поиск работает; добавление и перенос заблокированы. Восстановление повреждённых данных не входит в эту функцию; очистка данных сайта пользователем удалит каталог.
- Если в корректном массиве встретились одинаковые ID, сохранять первую запись для каждого ID, не создавать дубль. Об этом сообщить: «Повторяющиеся фильмы объединены». При одном ID с разными статусами используется статус первой записи.
- Сообщения сохранения доступны для программ чтения с экрана. Визуальные и клавиатурные требования проекта сохраняются.

## Примеры

1. Добавить фильм в «Хочу посмотреть», другой в «Просмотрено», перезагрузить страницу: оба фильма остаются на своих местах, счётчики верны.
2. Добавить три фильма, перенести один в другой список, перезагрузить: порядок, данные и статус перенесённого фильма сохранены.
3. После восстановления найти тот же ID и попытаться добавить повторно: новой записи нет. Одинаковые названия с разными ID остаются разными фильмами.
4. Открыть страницу с пустым localStorage: пустые списки без сообщения об ошибке.
5. Подменить запись localStorage ошибкой переполнения: добавление или перенос не меняет прежние данные и порядок, видно сообщение о неудачном сохранении. Разрешить запись и повторить: изменение применяется.
6. Подменить чтение исключением: сайт открывается, поиск доступен, каталог не перезаписывается и изменения заблокированы до перезагрузки.
7. Подменить сохранённые данные сломанным JSON, неизвестной версией или неверным статусом: понятное сообщение; исходная строка остаётся в хранилище.
8. Подменить данные корректным массивом с повторным ID: в каталоге одна запись на ID, выбран первый экземпляр и показано сообщение об объединении.
9. При восстановлении фильма без постера, года или рейтинга используются прежние заглушки. Поиск и его ошибки не меняют сохранённый каталог.

## Ограничения

- Ключ localStorage: `kinova.catalog`. Формат: объект с `version: 1` и массивом `films` в порядке добавления и последнего переноса от старых к новым. Интерфейс показывает каждый список в обратном порядке.
- Запись фильма: положительный безопасный целый ID; статус `planned` или `watched`; названия — строки или null; год — целое число или null; рейтинг — число от 0 до 10 или null; постер — HTTPS-адрес без логина и пароля или null. Поля нормализуются, неизвестные поля не сохраняются. Текст отображается как текст, без выполнения HTML.
- Версия проверяется до изменения данных. Для неизвестной версии не предпринимать автоматическую миграцию или очистку.
- Изменения сначала записываются в хранилище и только после успеха применяются к каталогу на странице. Не использовать localStorage.clear(), не затрагивать другие ключи сайта.
- API-ключ, история поиска и результаты выдачи не сохраняются. Каталог не отправляется серверу.
- Нет синхронизации устройств, браузеров и одновременно открытых вкладок. Для этой версии использовать одну вкладку: при нескольких вкладках более поздняя запись может заменить изменения другой.
- Локальный сайт и опубликованный сайт имеют отдельные хранилища. Автоматического переноса между ними нет. Режим приватного просмотра и настройки браузера могут ограничивать срок хранения.
- Нет экспорта, импорта и интерфейса восстановления повреждённого каталога. Личная оценка и отзыв появятся по отдельной спецификации; формат нужно будет расширить согласованно.
- Ошибки проверять на подменённом хранилище; не портить реальный каталог пользователя ради теста.
- Открытые проверки настоящего API, клавиатуры и 375px из предыдущих спецификаций остаются открытыми.

## Готово, когда

- [ ] Оба списка, данные, порядок и счётчики восстанавливаются после перезагрузки без API.
- [ ] Добавление и перенос сохраняются, дубли по ID исключены после восстановления.
- [ ] Пустое хранилище, ошибка чтения, ошибка записи, повреждённый JSON и неизвестная версия обработаны по требованиям.
- [ ] Неудачная запись не меняет каталог; повтор после восстановления доступа работает.
- [ ] Повреждённые и неизвестные данные не перезаписываются; чужие ключи localStorage не затрагиваются.
- [ ] Повторные ID объединяются по описанному правилу, неверные записи обрабатываются безопасно.
- [ ] Сообщения доступны; проверены клавиатура и ширина 375px.
- [ ] README описывает реализованное сохранение, ограничения и проверки. Личный опыт и отчёт автора не изменены.
- [ ] Пользователь проверил результат; коммит и push выполняются только после отдельного «да».

### Шаги

1. [ ] Сохранение добавления и переноса, восстановление корректного каталога. На странице новое пояснение о хранении в браузере. Проверка: добавить в оба списка; перенести фильм; перезагрузить и сверить порядок и счётчики. Минимальная обработка ошибок чтения и записи обязательна уже здесь: сбой не должен стирать данные или выдавать действие за сохранённое.
2. [ ] Проверка формата и защита при повреждении или недоступности хранилища. Проверка на подменённых данных: неверный JSON не перезаписан; ошибка записи оставляет каталог прежним; повторная успешная запись применяет действие. Дополнительно проверить неизвестную версию и повторные ID.
3. [ ] Итоговая проверка и документация. Проверка: восстановить каталог и найти уже добавленный фильм; убедиться, что ошибки поиска не меняют сохранённые списки; пройти сообщения и действия клавиатурой на ширине 375px. Обновить README и автоматические проверки.

Подтверждены запись добавления и переноса, восстановление обоих списков с порядком и счётчиками в новом контексте страницы без API, защита от повторного добавления восстановленного ID, сохранность прежних данных и порядка при ошибке записи, успешный повтор после снятия ошибки, отсутствие изменений чужого ключа. Прежние проверки поиска и списков также пройдены через Node.js-инструмент. В код включена базовая проверка формата при чтении, блокировка записи при ошибке чтения и безопасные сообщения; подробные отрицательные сценарии проверяются на шаге 2.
