# 005 — Размещение сайта

Статус: сайт размещён пользователем по адресу https://kinova-sigma.vercel.app/ . Пользователь расширил правило на Starts With /api/search. Повторная HTTP-проверка подтвердила общий порог для /api/search и /api/search.js: первые десять чередующихся запросов получили 503 без ключа, затем оба маршрута вернули 429. Добавлено отдельное сообщение для ограничения хостинга; изменённый клиент пока ожидает коммита и размещения. Остальные домены проекта отдельно не проверены. Рабочий ключ пока не настроен по текущему порядку работы.

## Для кого и зачем

Для автора учебного проекта и посетителей, которым нужна работающая HTTPS-ссылка на каталог. Код остаётся в публичном GitHub-репозитории, ключ API — только на сервере.

## Что должно быть

- Разместить проект на Vercel: страница и серверная функция `/api/search` работают на одном адресе. Локальный запуск через npm start сохраняется.
- Подготовить отдельный каталог сборки со статическими файлами по явному списку: index.html, styles.css, script.js. Не копировать в него всю рабочую папку. Серверный обработчик разворачивается как функция, а не как скачиваемый файл.
- Настройки сборки зафиксировать в репозитории. Использовать поддерживаемую хостингом LTS-версию Node.js, совместимую с проектом; проверить фактическую сборку перед публикацией.
- `.env.local`, `.env.example`, `.git`, серверный исходник, локальный сервер, тесты, спецификации и примеры прошлого проекта не должны раздаваться сайтом. Для таких путей — 404 без содержимого.
- Ключ пользователь самостоятельно задаёт в серверной переменной KINOPOISK_API_KEY в Vercel. Не запрашивать его в чате, не читать и не выводить значение при проверках. Ключ не нужен для сборки статических файлов.
- До добавления рабочего ключа настроить и проверить ограничение запросов к `/api/search` средствами хостинга. Порог — 10 запросов за 60 секунд на IP. Условие Request Path — Starts With `/api/search`, чтобы охватить также маршрут `/api/search.js`. Правило должно охватывать все доступные адреса развёрнутого проекта, а не только основной домен.
- Проверить доступность и условия правила в аккаунте. Не подключать платные услуги автоматически. Если требуемая защита недоступна, оставить поиск без рабочего ключа и выбрать доступный вариант защиты отдельным согласованным шагом.
- При блокировке хостингом показывать «Слишком много запросов к поиску. Подождите немного и попробуйте снова». Учесть HTTP 429 с ответом не в JSON. Это сообщение отличается от исчерпания квоты самого Kinopoisk API.
- Не считать ограничение по IP полной защитой общей квоты от множества посетителей. Зафиксировать ограничения выбранного механизма, порядок просмотра расхода в личном кабинете API и отключения поиска удалением серверного ключа с последующим переразвёртыванием.
- Квоту API при проверке защиты не расходовать: сначала использовать стенд без настоящего ключа. Для успешного поиска после настройки ключа достаточно одного ручного запроса, без нагрузочного теста настоящего API.
- На опубликованном сайте проверить поиск, карточки, два списка, перенос, оценку, отзыв и восстановление после F5. Подтвердить отсутствие ключа в ресурсах и запросах браузера к своей функции, а также в её ответах.
- Пройти клавиатурой основные действия и проверить ширину 375px, поля и области кнопок от 44px. Открытые браузерные пункты предыдущих спецификаций закрывать только по фактическим результатам.
- В README добавить проверенную HTTPS-ссылку, команды сборки, настройки размещения, ограничения каталога и фактически выполненные проверки. Личный опыт и отчёт автора не заполнять.

## Примеры

1. Выполнить сборку без ключа: в публичном каталоге только три файла страницы, секретов и серверного кода нет.
2. Открыть опубликованный сайт без серверного ключа: страница доступна, поиск сообщает о временной недоступности. Технические подробности не раскрываются.
3. До настройки настоящего ключа превысить настроенный порог запросов к своей функции: хостинг блокирует обращения, страница показывает сообщение о частых запросах, повтор после окончания ограничения возможен. Настоящий Kinopoisk API не вызывается.
4. Самостоятельно задать ключ в Vercel и переразвернуть сайт: поиск «Матрица» показывает результаты. Браузер обращается к `/api/search`, ключ отсутствует в запросе и ответе. Постеры могут загружаться с внешних адресов.
5. Проверить `/.env.local`, `/.git/config`, `/server.cjs`, `/tests/search.cjs`, `/README.md`: 404, содержимое файлов не раскрывается. `/api/search.js` на Vercel является дополнительным маршрутом функции, не скачиванием исходника; без q отвечает 400. Он должен попадать под то же ограничение частоты, что и `/api/search`.
6. Добавить фильм, сохранить оценку и отзыв, перенести его и нажать F5: данные остаются на опубликованном адресе. Локальный каталог автоматически на него не переносится.
7. Открыть сайт при ширине 375px: длинный отзыв не создаёт горизонтальную прокрутку; кнопки доступны, клавиатурный фокус виден.

## Ограничения

- Не создавать аккаунты, не принимать платные условия и не подключать оплату автоматически. Если инструменту нужен вход или недоступна панель хостинга, дать пользователю точную инструкцию для ручного шага; независимую подготовку файлов закончить заранее.
- Коммит и push — только после проверки пользователя и отдельного «да». Подключение GitHub к Vercel может включить автоматическое размещение после push: это явно отметить перед подключением и учитывать при последующих коммитах.
- Не публиковать рабочий ключ на незащищённом стенде. Адрес сайта добавлять как работающий только после фактической проверки; не придумывать URL.
- Без базы данных и авторизации: каталог остаётся в localStorage браузера. Разные адреса сайта и браузеры имеют отдельные каталоги.
- Счётчик в памяти одной серверной функции не заменяет ограничение на уровне хостинга: несколько экземпляров сервера не имеют общей памяти.
- Проверки на подменённых данных не заменяют проверку опубликованного сайта. Невыполненные пункты оставлять открытыми с причиной.
- Проверить публичность GitHub-репозитория без авторизации перед финальной сдачей проекта.
- Официальные источники для реализации: [сборка Vercel](https://vercel.com/docs/builds/configure-a-build), [конфигурация](https://vercel.com/docs/project-configuration/vercel-json), [ограничение запросов](https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting), [переменные окружения](https://vercel.com/docs/environment-variables). Доступность настроек сверить при размещении.

### Шаги

Повторная проверка после изменения правила пользователем: выполнены 10 чередующихся запросов к /api/search и /api/search.js (все 503), следующий запрос к /api/search получил 429, после него /api/search.js также получил 429. Затем проверка остановлена. Подтверждён общий лимит обоих маршрутов на основном домене с IP проверяющего. Это не подтверждает ограничения с других IP, регионов и доменов. Следующий этап — согласованный коммит клиента с сообщением о 429, его автоматическое размещение и самостоятельная настройка серверного ключа пользователем.

Проверки второго шага: основной сайт отвечает 200; .env.local, .git/config, server.cjs, tests/search.cjs и README.md — 404. Серия из 11 последовательных запросов к /api/search с одним тестовым названием дала десять 503 и один 429, затем остановлена. Значения секретов и содержимое ошибок не выводились. Выявлен дополнительный маршрут /api/search.js (400 без q); до рабочего ключа требуется расширение правила на префикс и повторная проверка. Клиент теперь отличает 429 с API_LIMIT от 429 с HTML, текстом или другим JSON хостинга. Автоматические проверки и сборка пройдены. Изменённый клиент пока не отправлен в GitHub и не опубликован. Защита всех адресов проекта и настоящий поиск ещё не подтверждены.

Проверки первого шага: сборка и повторная сборка создали только три разрешённых файла в dist, побайтно совпадающих с исходниками. На временной папке подтверждено, что .env.local не копируется, а неожиданный файл в dist останавливает сборку и остаётся нетронутым. Временные проверочные файлы убраны. Прежние тесты поиска, списков, хранения, оценки и отзыва прошли. Ключ сборкой не читается. Реальное развёртывание Vercel, работа функции на хостинге и недоступность служебных HTTP-путей пока не проверены. Защита частоты и рабочий ключ не настраивались; этап публикации не выполнялся.

1. [ ] Подготовка сборки и файлов Vercel. Проверка: выполнить сборку без ключа; сверить три публичных файла; запустить прежние тесты. Сайт ещё не размещать.
2. [ ] Защита частоты запросов и сообщение об ограничении. Подготовить клиентскую обработку и инструкцию настройки. Создать стенд без настоящего ключа, настроить доступное правило хостинга и проверить блокировку. При недоступности аккаунта указать точный ручной шаг и не считать защиту настроенной.
3. [ ] Серверный ключ и проверка сайта. Пользователь самостоятельно задаёт ключ; проверить настоящий поиск и недоступность файлов; пройти каталог, F5, клавиатуру и 375px. Добавить проверенную ссылку и результаты в README. Если нужен ручной доступ к панели, сообщить, что именно осталось сделать.
