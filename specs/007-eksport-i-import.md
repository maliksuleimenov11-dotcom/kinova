# 007 — Экспорт и импорт каталога

Статус: первые два шага приняты пользователем и закоммичены. После «делай» реализован третий шаг — подтверждение и безопасное объединение. Автоматические проверки и сборка пройдены; ручная проверка, коммит третьего шага и итоговый четвёртый шаг ещё впереди.

Проверки третьего шага: tests/search.cjs проверяет приоритет текущего ID, статуса, оценки и отзыва; добавление новых записей с сохранением их личных полей; одну запись в localStorage при успехе; неизменность каталога и предварительного результата при ошибке записи; успешный повтор; отсутствие повторной записи при двойном подтверждении и повторном импорте; восстановление и порядок; импорт версии 1 в пустой каталог с записью версии 2; сброс локального поиска и вызов перевода фокуса. Изменение хранилища после предварительного результата блокирует импорт без перезаписи чужих данных и требует перезагрузки. Все проверки и сборка прошли через Node.js-инструмент без настоящего API. Реальные F5, выбор файла, клавиатура и 375px остаются для ручной проверки. Описания предыдущих шагов ниже — история их проверки, а не текущие ограничения.

Проверки второго шага: tests/search.cjs дополнен файлами версий 1/2, UTF-8 BOM, предварительными числами и повторными ID, буквальным именем файла, сохранностью существующих данных, блокировкой прямых действий с каталогом, отменой, повторным выбором файла, границей 5 МиБ до чтения, неверным JSON/версией/отзывом, ошибкой чтения, отсутствием новых записей и блокировкой выбора при открытом редакторе. Проверено отсутствие записи и сетевых запросов при проверке файла; отменённый результат чтения не открывает предварительный результат. Все прежние тесты и сборка прошли через Node.js-инструмент на синтетических данных. Реальный диалог выбора, клавиатура и 375px пока не проверены. Добавление из файла намеренно недоступно до третьего шага.

Проверки первого шага: tests/search.cjs проверяет полный JSON версии 2 с порядком и личными полями при скрытом поиском фильме; исключение неизвестного поля и черновика; сохранность localStorage и открытой формы; отсутствие запросов к сети; имя файла с локальной датой; пустой каталог; ошибку скачивания с успешным повтором, удаление временной ссылки и освобождение адреса Blob; блокировку экспорта при повреждённых данных. Прежние тесты и сборка пройдены через Node.js-инструмент. Реальные личные копии и ключи не использовались. Браузерный инструмент недоступен: реальное сохранение файла, клавиатура и 375px пока не проверены.

Большая функция: пользователь сможет скачать личный каталог фильмов в файл и восстановить его из файла в другом браузере, сохранив списки, оценки и отзывы.

## Для кого и зачем

Для владельца каталога, который хочет сделать резервную копию перед очисткой браузера или перенести коллекцию на другое устройство. Файл позволяет перенести данные вручную без регистрации и сервера хранения.

## Что должно быть

### Скачать каталог

- В разделе «Мой каталог» появляется кнопка «Скачать каталог» и пояснение: «Файл содержит ваши фильмы, оценки и отзывы. Храните его у себя».
- По кнопке браузер предлагает сохранить JSON-файл с именем `kinova-catalog-YYYY-MM-DD.json`; дата берётся из локальной даты браузера.
- Экспорт содержит весь сохранённый каталог, включая карточки, скрытые локальным поиском: ID, названия, год, рейтинг API, адрес постера, статус списка, личную оценку и отзыв. Порядок записей сохраняется.
- Несохранённые черновики, поисковые запросы, ключ API и другие данные localStorage в файл не попадают. Открытая форма оценки и отзыва не закрывается.
- Пустой каталог можно скачать: получается корректный файл с пустым массивом фильмов.
- Экспорт не меняет каталог и localStorage, не вызывает API. При ошибке подготовки файла — «Не удалось подготовить файл. Попробуйте ещё раз».
- Не утверждать, что файл записан на диск: сайт может подтвердить только подготовку и передачу файла браузеру. Пользователь может отменить скачивание.

### Восстановить из файла

- Кнопка «Выбрать файл каталога» открывает выбор одного JSON-файла с устройства. Отмена выбора ничего не меняет. Один и тот же файл можно выбрать повторно.
- Принимается файл размером не больше 5 МиБ (5 242 880 байт). Размер проверяется до чтения; расширение и MIME-тип не заменяют проверку содержимого.
- До изменения каталога приложение читает и проверяет весь файл. Поддерживаются форматы каталога версий 1 и 2; неизвестная версия, неверная структура или неверная запись отклоняют весь импорт без частичного добавления.
- Для версии 1 личная оценка становится null, отзыв — пустой строкой. Для версии 2 сохраняются оба поля. Применяются правила проверки данных из спецификаций 003 и 004; неизвестные поля не переносятся.
- Повторные ID внутри файла объединяются: используется первая корректная запись каждого ID в исходном порядке. Неверная запись, даже среди повторов, отклоняет файл целиком.
- Текущий каталог объединяется с файлом. Если ID уже есть в текущем каталоге, существующая запись целиком сохраняется, включая список, оценку и отзыв. Другие ID добавляются. Импорт не перезаписывает текущие впечатления и не создаёт дубли.
- После проверки показывается предварительный результат: имя файла как обычный текст, число уникальных фильмов, сколько добавится, сколько уже есть и сколько повторов внутри файла пропущено. Подпись: «Ваши существующие фильмы останутся без изменений».
- До нажатия «Добавить из файла» ничего не записывается. Рядом кнопка «Отмена импорта», которая убирает предварительный результат без изменения каталога.
- Если файл пуст или все ID уже есть, показать «Новых фильмов нет». Кнопка подтверждения недоступна; запись в localStorage не выполняется.
- Пока открыт предварительный результат, изменения каталога и открытие редактора личных полей временно заблокированы. Поиск остаётся доступным. Это сохраняет соответствие предварительных чисел итоговому импорту. После отмены или завершения блокировка снимается.
- Выбор файла при открытом несохранённом редакторе недоступен. Пояснить: «Сначала сохраните или отмените редактирование фильма». Экспорт по-прежнему доступен и содержит только сохранённые значения.
- При подтверждении выполняется одна запись полного объединённого каталога в localStorage в версии 2; только после её успеха обновляются карточки и счётчики. Ошибка записи оставляет данные и порядок прежними, предварительный результат — открытым; можно повторить или отменить.
- В пустом каталоге импорт восстанавливает исходный порядок обоих списков. При объединении текущие записи сохраняют свой порядок; новые записи файла добавляются после текущих во внутреннем порядке хранения, поэтому показываются перед текущими в соответствующих списках.
- После успешного импорта очистить локальный запрос каталога, чтобы показать все восстановленные фильмы. Выдачу внешнего поиска не очищать; статусы её карточек обновить. Сообщение: «Добавлено фильмов: N. Уже были в каталоге: M».
- После F5 восстановленные фильмы, статусы, оценки и отзывы остаются. Операции полностью локальные, квота API не расходуется.

### Сообщения и доступность

- Слишком большой файл: «Файл больше 5 МиБ. Выберите файл меньшего размера».
- Ошибка чтения: «Не удалось прочитать файл. Выберите его ещё раз».
- Ошибка JSON или данных: «Не удалось импортировать каталог: файл повреждён или имеет неподдерживаемый формат. Ваш каталог не изменён».
- Ошибка записи: существующее сообщение «Не удалось сохранить изменения. Проверьте доступ к хранилищу браузера и попробуйте снова».
- Имена файлов, названия и отзывы отображаются как текст, HTML не выполняется. Сообщения доступны программам чтения с экрана, кнопки управляются клавиатурой.
- После подготовки предварительного результата фокус на его заголовке, после отмены — на кнопке выбора файла, после успеха — на заголовке каталога. Ошибки доступны без потери введённых ранее данных.
- Русский интерфейс, работа при ширине 375px без горизонтальной прокрутки; поля высотой от 44px, области кнопок минимум 44 × 44px, видимый фокус.

## Примеры

1. В каталоге один фильм в планах и два просмотренных с оценками и отзывами. Скачать файл и импортировать в пустой каталог другого браузера: три фильма, статусы, личные поля и порядок совпадают с исходными после F5.
2. Скрыть часть каталога локальным поиском и скачать: файл содержит все фильмы, а не только видимые карточки.
3. Текущий каталог содержит ID 1 с оценкой 8, файл — ID 1 с оценкой 3 и ID 2. До подтверждения показать: добавится 1, уже есть 1. После подтверждения ID 1 остаётся с оценкой 8, ID 2 добавлен.
4. Два фильма имеют одинаковое название, но разные ID: импортируются как разные записи. Два экземпляра одного ID внутри файла дают одну запись и учитываются как повтор.
5. Выбрать файл, посмотреть числа и отменить: каталог и исходная строка localStorage не меняются. Выбрать тот же файл снова — проверка запускается повторно.
6. Выбрать сломанный JSON, неизвестную версию, файл с неверным статусом или отзывом из 501 символа: ошибка, ни одной записи не добавлено. Файл из 5 242 881 байта отклоняется до чтения.
7. Смоделировать ошибку записи при подтверждении: старый каталог остаётся целиком, предварительный результат открыт. Восстановить запись и повторить: добавление успешно, дублей нет.
8. Выбрать файл версии 1: фильмы восстановлены, личная оценка не указана, отзыв пуст. После успешного импорта сохранена версия 2.
9. Импортировать тот же файл второй раз: «Новых фильмов нет», записи в localStorage нет. Импорт пустого массива также ничего не меняет.
10. При открытом отзыве с черновиком скачать каталог: в файле прежний сохранённый отзыв, черновик на странице остаётся. Выбор файла импорта доступен после сохранения или отмены редактора.

## Ограничения

- Формат файла — объект `{ "version": 2, "films": [...] }`, совместимый с текущим каталогом `kinova.catalog`. Читается также версия 1. Выгружаются только разрешённые поля нормализованных фильмов, а не всё содержимое localStorage.
- Экспорт и импорт не требуют сети и не отправляют файл серверу. Постеры представлены адресами, а не изображениями: перенос каталога не гарантирует доступность постеров без интернета.
- Без режима замены всего каталога, удаления записей, выбора отдельных фильмов и ручного разрешения конфликтов в этой версии. При совпадении ID приоритет всегда у текущего каталога.
- Если текущее хранилище не прочитано или повреждено, экспорт и импорт заблокированы, чтобы не выдать пустой каталог за резервную копию и не затереть исходные данные. Существующее сообщение о проблеме остаётся. Эта функция не является восстановлением повреждённого localStorage поверх ошибки.
- Перед подтверждением импорта проверить, что сохранённая строка `kinova.catalog` не изменилась после предварительного чтения. Если другая вкладка изменила её, не записывать импорт и предложить перезагрузить страницу; предварительный результат закрыть. Полной синхронизации вкладок нет, рекомендуется одна вкладка.
- Личный файл содержит отзывы, поэтому пользователь сам выбирает, кому его передавать. Не добавлять реальные резервные копии в Git; для автоматических проверок использовать только синтетические фильмы.
- Не менять серверную функцию, API-ключ, правила Firewall и формат основных личных полей. Кодировать JSON в UTF-8; допустимо обработать начальный UTF-8 BOM при чтении.
- Не отключать текущую защиту от повреждённых данных и не выполнять автоматическую очистку хранилища. При ошибке импорта исходный файл также не изменяется.
- Ранее открытые подробные проверки клавиатуры и точных размеров не считать выполненными без фактической проверки.

- [ ] Экспорт создаёт файл всего сохранённого каталога с версией 2, порядком и личными полями без секретов и черновиков.
- [ ] Импорт в пустой браузер восстанавливает данные после F5; версии 1 и 2 поддержаны.
- [ ] До подтверждения показаны корректные числа; отмена и отсутствие новых записей ничего не меняют.
- [ ] При объединении существующие ID и личные данные сохранены, повторы не появляются.
- [ ] Неверные и слишком большие файлы отклоняются целиком, без чтения лишнего или частичного импорта.
- [ ] Ошибка записи не меняет каталог; повтор после восстановления доступа работает. Изменение хранилища другой вкладкой обнаруживается до записи.
- [ ] Черновик редактора, локальный поиск, счётчики и статусы внешней выдачи согласованы с требованиями.
- [ ] Нет запросов к API, передачи файла серверу, изменения чужих ключей localStorage и записи реальных копий в Git.
- [ ] Пройдены автоматические проверки, прежние тесты и сборка; ручная проверка файла, клавиатуры и 375px выполнена либо явно отмечена незавершённой.
- [ ] После завершения README описывает фактические возможности и проверки. Личный опыт и отчёт автора не заполнены агентом.

## Шаги

1. [ ] **Скачивание каталога.** На экране появляется «Скачать каталог» и пояснение о содержимом файла. Проверка: скачать каталог при активном локальном поиске; открыть JSON и сверить оба списка, порядок, оценки и отзывы; убедиться, что каталог и черновик не изменились. Дополнительно проверить пустой каталог и ошибку подготовки файла.
2. [ ] **Выбор файла и предварительная проверка.** На экране появляются выбор файла, предварительные числа и «Отмена импорта»; применение пока недоступно и прямо обозначено как следующий шаг. Проверка: выбрать корректный файл и сверить числа; выбрать неверный или слишком большой файл и увидеть ошибку; отменить и убедиться, что каталог не изменился. Проверить повторный выбор того же файла и блокировку при открытом редакторе.
3. [ ] **Подтверждение и безопасное объединение.** Становится доступна кнопка «Добавить из файла», добавление применяется после успешной записи. Проверка: импортировать файл с одним существующим и одним новым ID; убедиться, что прежняя оценка не перезаписана; нажать F5 и сверить списки и порядок. Автоматически проверить ошибку записи, успешный повтор и изменение хранилища другой вкладкой.
4. [ ] **Итоговая проверка и README.** Проверка: перенести скачанный файл в другой браузер и сверить каталог; импортировать повторно без дублей; пройти выбор, отмену и подтверждение клавиатурой на ширине 375px. Дополнить проверки форматов, лимита размера и отсутствия сетевых запросов, запустить прежние тесты и сборку, обновить README фактическими результатами.
