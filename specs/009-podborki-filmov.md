# 009 — Популярные фильмы и премьеры месяца

Статус: первый шаг принят пользователем и закоммичен. На втором шаге подготовлены серверная загрузка, часовые CDN-заголовки и кеш открытой страницы; демонстрационные данные удалены. Автоматические проверки, локальные маршруты и сборка прошли. Настоящие подборки, CDN HIT и браузерная проверка ещё не выполнены. Коммит и push второго шага ожидают согласования; добавление в каталог — третий шаг.

Проверки второго шага: tests/discover.cjs включён в npm test через существующий tests/search.cjs. Проверены методы и наборы параметров, допустимая пара месяцев на границе года, отсутствие ключа, фиксированные API-адреса, одна внешняя попытка, нормализация и безопасные ссылки, уникальные ID и не более 20 карточек, отсутствие рейтинга премьер, проверка календарной даты, ошибки 401/403/402/429/500, повреждённый ответ, сеть и тайм-аут. Успех имеет часовой Vercel-CDN-Cache-Control, ошибки — no-store. Клиентские проверки подтверждают отсутствие фоновых запросов, кеширование успешной и пустой выдачи, повтор до/после TTL, отсутствие кеширования ошибок, сообщение 429 хостинга с HTML и неизменность каталога. Прежние тесты и сборка прошли через Node.js-инструмент на подменённых API и часах без настоящего ключа.

До публикации проверен охват новых путей действующим правилом Firewall: первые 10 чередующихся обращений к /api/search-discover и /api/search-discover.js с kind=invalid получили 404, затем оба маршрута получили 429. Это проверка префикса правила на основном домене, до размещения самой функции, без обращения к Kinopoisk API. Локальный сервер возвращает 400 на неверные параметры по обоим путям. После размещения проверить реальную загрузку и CDN HIT отдельно; заголовки сами по себе не означают подтверждённый HIT. История первого шага ниже относится к прежнему тестовому режиму.

Проверки первого шага: tests/search.cjs дополнен формой, переключением полей без загрузки, сохранением заголовка прежней выдачи, состоянием загрузки, блокировкой повтора, датами премьер, отсутствующим рейтингом и годом, пустым результатом, ошибкой с повтором и ограничением 20 карточками. На подменённых часах проверены граница UTC+5, декабрь/январь, високосный февраль и обновление разрешённой пары при смене месяца без автоматической загрузки. Подтверждены отсутствие fetch и изменения сохранённого каталога при работе подборок. Прежние тесты и сборка прошли через Node.js-инструмент. Данные вымышленные, постер создан локально в SVG. Реальный браузер, клавиатура и 375px не проверены; первый шаг оставлен без полного флажка до ручной проверки.

Большая функция: пользователь сможет посмотреть подборку популярных сейчас фильмов или премьеры текущего и прошлого месяца и добавить понравившийся фильм в личный каталог.

## Для кого и зачем

Для человека, который ещё не выбрал название для поиска и хочет найти фильм среди готовых подборок. Раздел помогает узнавать новинки и выбирать их для просмотра.

## Что должно быть

### Подборки и управление

- На странице отдельный раздел «Что посмотреть» с выбором «Популярные сейчас» или «Премьеры месяца» и кнопкой «Показать подборку».
- Для премьер доступны только текущий и предыдущий календарные месяцы. В вариантах выбора показаны название месяца и год, например «Январь 2027» и «Декабрь 2026». Для популярного списка выбор месяца скрыт и не влияет на запрос.
- Границы месяцев вычислять одинаково на клиенте и сервере по UTC+5. В запросе передавать конкретный год и месяц, а не относительное «прошлый». Переход декабря в январь учитывается.
- При открытии страницы, изменении вида подборки или месяца запрос не отправляется. Загрузка — только по кнопке или Enter в форме.
- До первой загрузки: «Выберите подборку и нажмите „Показать подборку“». Пока идёт запрос: «Загружаем подборку…», повторная отправка заблокирована.
- При начале новой загрузки прежние карточки очищаются. При простом изменении полей без отправки заголовок над уже показанными результатами продолжает обозначать именно загруженную подборку, чтобы не выдавать прежние данные за новый выбор.
- Показывать не больше первых 20 фильмов в порядке ответа API, без пагинации. Подпись «Показано N фильмов» и пояснение об ограничении 20 карточками. Не называть показанный фрагмент полной выдачей.
- «Популярные сейчас» — текущая подборка поставщика, а не личный рейтинг и не месячный исторический топ. «Премьеры месяца» — премьеры в России, а не топ по рейтингу.

### Карточки и личный каталог

- В карточке — постер, название, год и «Рейтинг API». Отсутствующие поля используют существующие заглушки.
- Для премьер дополнительно показать «Премьера в России: ДД.ММ.ГГГГ» из premiereRu. Если корректной даты нет, «Дата премьеры не указана». Дату интерпретировать как календарную, без смещения часового пояса.
- В выдаче премьер рейтинг API отсутствует: показывать «Нет рейтинга». Не делать дополнительные запросы по каждому фильму ради рейтинга.
- Кнопки «Хочу посмотреть» и «Просмотрено» добавляют фильм по прежним правилам. При уже существующем ID показывается текущий статус, дубль не создаётся.
- Добавление из подборки обновляет каталог, статусы верхней поисковой выдачи и всех карточек подборки с тем же ID. Перенос, удаление, отмена удаления и импорт также обновляют статусы подборки без повторного запроса API.
- Добавление из подборки является успешным изменением каталога и завершает прежнюю возможность отмены удаления; ошибка записи её сохраняет. Применяются текущие блокировки при чтении/ошибке хранилища, редактировании и предварительном импорте.
- Уже открытый черновик другого фильма не теряется. При добавлении фокус переходит на обновлённый статус именно нажатой карточки подборки, затем можно продолжить Tab.
- Дата премьеры нужна только в выдаче подборки: формат личного каталога и экспорта версии 2 не расширять. В каталог сохранять только прежние поля фильма.
- Загрузка подборки, смена месяца и ошибки не меняют localStorage и не завершают отмену удаления. Локальный поиск каталога и внешний поиск по названию работают независимо.

### Сервер, лимит API и кеш

- Браузер запрашивает только свою серверную функцию `/api/search-discover`; исходник `api/search-discover.js`. Оба варианта пути начинаются с `/api/search`, поэтому должны попадать под уже настроенное правило Firewall Starts With `/api/search`.
- Локальный сервер должен поддерживать тот же маршрут. При размещении отдельно проверить дополнительный путь `/api/search-discover.js` и охват обоих адресов ограничением запросов. Правило не расширять на статические файлы.
- Только GET. Два разрешённых набора параметров: `kind=popular` либо `kind=premieres&month=YYYY-MM`. Повторные и посторонние параметры, неизвестный kind и месяц вне разрешённой пары отклонять до обращения к API. URL запроса на клиенте собирать в фиксированном порядке параметров.
- Для популярных использовать `/api/v2.2/films/collections?type=TOP_POPULAR_MOVIES&page=1`. Для премьер — `/api/v2.2/films/premieres` с year и month из разрешённого списка API. Ввод пользователя не может задать внешний URL или произвольный тип коллекции.
- Ключ — только существующая серверная переменная KINOPOISK_API_KEY и заголовок X-API-KEY. Не читать настоящий ключ для разработки и проверок, не добавлять в Git, клиент, ответы, примеры или логи.
- На один запрос без кеша — максимум одно обращение к API. Нет автоматических повторов, фоновой загрузки всех месяцев, предварительной загрузки и запросов за деталями фильмов. Время ожидания API — до 8 секунд, клиента — до 12 секунд.
- Возвращать нормализованные карточки с положительными целыми ID и безопасными HTTPS-адресами постеров. Не проксировать исходные ошибки, заголовки и секреты. Повторные ID в показанном ответе объединять с приоритетом первого; карточек не больше 20.
- Успешные общедоступные ответы, включая корректную пустую выдачу, кешировать на CDN Vercel на 3600 секунд. Предусмотреть соответствующие cache-заголовки только для успешного результата. Не включать в публичный кеш личный каталог, статусы пользователя и отзывы.
- Для браузера требовать повторную проверку свежести ответа; серверный кеш задавать отдельным Vercel-CDN-Cache-Control. Не кешировать ошибки, отсутствие ключа, неверные параметры, тайм-аут и отказы API: для них no-store, без успешного TTL.
- В текущей странице повторная загрузка того же вида и месяца в течение часа использует уже полученную успешную выдачу без нового fetch. При этом статусы добавления рассчитываются заново из текущего каталога. После часа следующее нажатие делает обычный запрос; фонового обновления нет. Ошибка не сохраняется в этот кеш.
- Подпись: «Подборки используют общий лимит API сайта. Данные могут обновляться с задержкой до часа». При результате из памяти страницы можно указать «Уже загруженная подборка».
- Серверное кеширование снижает расход, но не гарантирует один запрос в час на весь сайт: разные URL, регионы, одновременные промахи кеша и новые размещения могут привести к дополнительным обращениям. Не обещать точную экономию и не считать память одного экземпляра функции общим кешем.
- После отключения ключа уже кешированная публичная подборка может оставаться доступной до часа. Это данные фильмов, не секрет; для немедленного отключения нужен сброс кеша средствами хостинга.

### Ошибки и доступность

- Пустой ответ: «В этой подборке пока нет фильмов. Выберите другую подборку или месяц».
- Сеть, тайм-аут и неожиданный формат: «Не удалось загрузить подборку. Проверьте соединение и попробуйте снова».
- Подтверждённая квота или частотный лимит внешнего API: «Лимит API исчерпан. Попробуйте позже». Не обещать время сброса.
- Блокировка Firewall (429, в том числе HTML или текст): «Слишком много запросов. Подождите немного и попробуйте снова».
- Отсутствующий или неверный ключ: «Подборки временно недоступны». Повторная попытка только по кнопке, она снова доступна после завершения ошибки.
- При смене календарного месяца обновить разрешённую пару при следующем действии пользователя. Если ранее выбранный месяц вышел из пары, выбрать текущий и попросить нажать кнопку снова; не запускать скрытый запрос.
- Русские подписи, доступные сообщения загрузки и результата, управление клавиатурой, видимый фокус. Поля высотой от 44px, области кнопок минимум 44 × 44px, ширина 375px без горизонтальной прокрутки.

## Примеры

1. Открыть страницу и переключить вид подборки: запросов нет. Нажать «Показать подборку»: один запрос к своей функции, затем не более 20 карточек.
2. Выбрать премьеры прошлого месяца: над результатами указан выбранный месяц и пояснение о премьерах в России. На карточках есть дата, но нет выдуманного рейтинга.
3. На тестовой дате январь 2027 доступны январь 2027 и декабрь 2026. На дате первого числа следующего месяца пара обновляется без автоматического запроса.
4. Повторно нажать кнопку с теми же параметрами до истечения часа: в этой странице нового fetch нет. После переноса фильма в другой список его статус в кешированной выдаче правильный.
5. Смоделировать два одинаковых серверных запроса на Vercel: после прогрева проверить признак попадания в CDN-кеш. Ошибочный ответ не должен получать часовой TTL. Не проверять это большим количеством запросов к настоящему API.
6. Добавить фильм из подборки: он появляется в каталоге, статус совпадает в подборке и обычном поиске. Попытка повторного добавления того же ID не создаёт копию.
7. Удалить добавленный фильм и отменить удаление: статус в подборке меняется в обе стороны без загрузки подборки заново. Импорт и перенос дают такое же согласованное поведение.
8. Смоделировать пустую выдачу, сеть, тайм-аут, отказ авторизации, лимит API и 429 хостинга: понятные сообщения; каталог и черновик не изменились; кнопку можно нажать снова.
9. Подменить месяц, передать неизвестный kind или дополнительные параметры: сервер не обращается к API, не возвращает секреты и не кеширует ошибку.
10. После успешного ответа истёк час: до нового нажатия запросов нет; следующее нажатие снова обращается к своей функции.

## Ограничения

- Без исторического месячного топа, общего топ-250, выбора произвольного месяца, рейтингов премьер через дополнительные запросы, пагинации и платных сервисов.
- Не называть популярность «топом за месяц»: документированного параметра истории популярности здесь нет. Премьеры не сортируются по оценке.
- Серверный ключ и текущие правила безопасности сохраняются. Настоящую квоту не расходовать для автоматических тестов; использовать подменённые API, часы и кеш. Один реальный запрос каждого выбранного типа — только на финальной ручной проверке.
- До публичного запуска маршрута проверить его охват Firewall. Учесть, что push запускает автоматическое размещение Vercel; коммит и push — только после проверки пользователя и отдельного «да».
- Локальный запуск без CDN не подтверждает работу кеша хостинга. Заголовки и отсутствие лишних обращений проверяются автоматически, фактический HIT — отдельно на Vercel. Не объявлять HIT подтверждённым только по наличию заголовков в коде.
- Состав и порядок подборок меняются у поставщика: не проверять конкретное количество реальных фильмов и конкретные рейтинги как постоянные значения.
- Старые открытые проверки клавиатуры и точных размеров не считать выполненными без проверки.
- Источники для реализации: [OpenAPI Kinopoisk API Unofficial](https://kinopoiskapiunofficial.tech/documentation/api/openapi.json), [кеширование функций Vercel](https://vercel.com/docs/caching/cdn-cache), [cache-заголовки](https://vercel.com/docs/caching/cache-control-headers). Перед реализацией сверить актуальные схемы; запросы с настоящим ключом для чтения документации не нужны.
